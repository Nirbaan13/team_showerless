# Prospective frozen v3 evaluation runners

Implementation and verification use toy files and declared development data only. No final pixels or reserved synthetic draws have been inspected or generated by this task. The coordinator creates and externally anchors the actual final freeze after source review and candidate export.

## Implementation plan and ownership

1. Write failing guards for missing or tampered freezes before scientific loading.
2. Validate model, metadata, source, acquisition, download and input hashes; fixed profiles; canonical parent/seed maps; package paths; and software versions using only standard-library file reads.
3. Generate native latents once, then evaluate both frozen systems in separate primary and secondary profiles, retaining every planned derivative.
4. Simulate each independent synthetic field once, then evaluate the same images and truth through both systems and profiles.
5. Test pairing, empty detections, failures, caps, geometry and atomic output; verify real development execution before freezing prospective final source.

Owned files are `experiments/v3_evaluation/run_native.py`, `run_synthetic.py`, `test_runners.py`, and this document. The coordinator owns `paired.py` and its tests. Production, training and model artifacts are not modified by these runners. Runtime inference never fits.

## Trusted freeze contract

Both CLIs require a JSON manifest and its SHA-256 supplied independently:

```text
PYTHONPATH=backend/inference PYTHON -m experiments.v3_evaluation.run_native --freeze FREEZE.json --freeze-sha256 EXTERNAL_SHA256 --output-dir OUTPUT_NATIVE
PYTHONPATH=backend/inference PYTHON -m experiments.v3_evaluation.run_synthetic --freeze FREEZE.json --freeze-sha256 EXTERNAL_SHA256 --output-dir OUTPUT_SYNTHETIC
```

Run from repository `ml/pvusatov/`. Replace `PYTHON` with the approved environment interpreter. There is no seed-range override, parent discovery, network access, fitting, output overwrite, or implicit final authorization.

Required manifest fields are:

- `schema_version: 1`, `status: "frozen"`, `scope: "development" | "final"`, and explicit `authorized_final`.
- `package_root`, an absolute namespaced inference directory. The complete required named source inventory is exported as `run_native.SOURCES`; each reference has exactly `path` and `sha256`. It includes both runners, paired accounting, detector, preparation, model, contracts, package initializers, runtime entry/CLI/pipeline/render sources, simulation and native-injection helpers. Paths must resolve to those files within the configured package. Core deployment source may be finalized separately before the actual freeze.
- `versions`, exactly `run_native.versions()`: Python, NumPy, SciPy, Astropy, ONNX Runtime and Pillow. Validation checks these without importing scientific modules.
- `models.baseline` and `models.candidate`, each with `artifact: {path, sha256}`, `metadata: {path, sha256}`, and `psf_sigma`. Arbitrary artifact/metadata filenames are supported; verified copies receive the production loader's expected names in a private temporary directory. Copied hashes are checked again before loading. Metadata's declared artifact hash must agree. A metadata `detector_profile`, when present, must match the frozen primary options and selected sigma. The production loader enforces its embedded graph/metadata contract after preflight.
- `options.primary` is `run_native.OPTIONS` plus `min_speed: 0.5`; `options.secondary` differs only by `min_speed: 0.005`. Baseline sigma is 1.2; the single selected candidate sigma is 1.2 or 0.8. No other per-system detector difference is accepted.
- `runtime` contains exactly `workers` (1–6), `math_threads: 1`, `max_frames: 32`, and `max_grid: 512`. One worker is the conservative memory setting. Thread variables are set before scientific imports and each ONNX session uses its production single-thread configuration.
- `native.region` specifies width/height in arcminutes, pixel scale in arcseconds and motion masks. `native.matrix` is exactly `run_native.MATRIX`. `native.acquisition_manifests` is a nonempty list of file references. `native.parents` is a canonical sorted list of unique IDs, fixed seeds, center coordinates and a `downloads_manifest` reference. Each download manifest lists observation paths and SHA-256 values; all byte hashes validate before any FITS reader. Optional frame IDs default to filename stems. Repeated exposure bytes are rejected.
- `synthetic` specifies an explicit unique sorted seed list, calibration-bank file reference and `generator: {extended_every_nth_field: 3, varying_psf: true}`.
- Optional `provenance_files` lists additional hashed selection/export/parity reports to validate before execution.

The final baseline artifact must equal deployed v2 SHA-256 `dde04fc3996be19150c57ca0399a7de52d6e7b62b2b65731133159585a3580a9`. Final native execution requires exactly ten sorted parent IDs mapped in order to seeds 2200001–2200010, with exactly eight listed and eight independently prepared exposures per parent. Final synthetic execution requires exactly seeds 2000000–2001999. `scope: "final"` additionally requires `authorized_final: true` in the externally anchored manifest. Development permits seeds 1900000–1999999 only and rejects final/quarantine native paths.

Missing fields, altered files, incompatible options, wrong versions, incorrect metadata declarations, missing trust anchors and invalid maps fail before scientific loading. Native-byte hashing is permitted before readers and does not interpret pixels. The actual final freeze is coordinator-owned; the development fixtures are not an authority to open final data.

## Native pairing and measurement semantics

Each parent uses nine speeds (0.01, 0.03, 0.1, 0.3, 1, 4, 10, 25, 50 pixels/hour), six seeded random positions/directions and five brightness multipliers (3, 6, 12, 24, 48): 270 planned derivatives. All four system/profile caches receive exactly the same latent positions and constant injected flux. Positions are never moved into coverage.

Brightness normalization exactly follows the declared expanded development generator: median projected response peak at finite covered centers; otherwise any positive trajectory response; otherwise the positive field-center response; finally unit normalization if no response exists. The field-center fallback sets normalization only and never relocates the injected source. The local native ePSF/WCS, interpolation, production masks and per-epoch recentering are reused.

Controls run independently with each detector configuration. Their identities remain unknown. Every derivative records its own preexisting-control match and attribution eligibility. Unknown real candidates have label −2; injected matches have truth ID 0. Matching is evaluation-only and requires all linked positions to lie within 1.5 pixels of the known trajectory. Actual epochs, measured positions, true and measured spans, offsets and candidate indices are recorded. A near-static spatial match is not established motion. The coordinator reports all planned trials alongside common-attributable and geometric/resolved-motion diagnostics.

When the selected sigma is 1.2, identical detector settings reuse the same tracks; both frozen models score the resulting six observed features independently. Cache metadata explicitly records this reuse. There are no forced template positions or manufactured fit RMS values.

## Synthetic pairing

The unchanged `simulate_v2` generator creates each independent field once. Images and truth are shared by both systems and profiles. Full field seeds, cadence/nuisance metadata, physical-hour times, shapes and known trajectories are retained. Candidate matching chooses the closest eligible truth trajectory after detection; duplicate tracks do not count as multiple recovered objects. Synthetic unmatched candidates are known simulation negatives (−1), distinct from unknown real candidates.

Caches retain the common top-level metadata expected by `validate_cache_pair`; synthetic time/shape values vary per field and are therefore stored in field records, with empty top-level arrays explicitly indicating this variation. Synthetic fields have no per-field native `parent_id`, so `paired_report` groups them by independent seed. Native derivatives remain grouped by parent.

## Outputs, bounds and failures

Each parent/profile/system cache is streamed to a temporary gzip file, closed/fsynced and atomically published only when complete. This avoids buffering 270 candidate-heavy derivatives. Synthetic submissions are bounded in batches; Python 3.12-compatible future dispatch limits queued results, and scientific/model initialization occurs once per worker context. No velocity cube or training state is allocated.

Caches contain frozen hashes, parsed model metadata, options, versions, source/input provenance, scores, model/detector CPU and wall timings, peak-cap flags, control diagnostics and worker peak RSS. Declared detector bounds remain enforced by the unchanged production detector. A cap is an incomplete search diagnostic, not a false-positive count or a completeness guarantee.

Errors retain all planned identities. Failed native preparation produces explicit failures with unknown positions/flux (`null`), not fabricated flux; its planned one-source denominator remains one. Detection and scoring failures are explicit. Unscored measured features/geometry are preserved separately while the scored candidate list is empty. A simulation/calibration failure leaves the true object denominator unknown, explicitly flags that condition and invalidates completion.

An atomic `run-native-manifest.json` or `run-synthetic-manifest.json` records every cache hash, count and error summary. `evaluation_complete` is false after any runtime error or unknown truth accounting. The CLI exits 2 after writing such incomplete results. Missing run manifests, partial outputs, incomplete status, or source/hash failures cannot support promotion. The coordinator's recovery, runtime and integration gates remain separate; these tools never select or promote a candidate.

Native injection remains a projected registered-image experiment: no raw-detector forward simulation, added photon noise or variance update is claimed; source flux is held fixed across varying passbands. Scores remain uncalibrated ranking values, and unmatched real controls never supply precision estimates.
