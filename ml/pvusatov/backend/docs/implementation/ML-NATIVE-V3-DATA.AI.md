## Acquisition and native physical data

The acquisition code is `backend/inference/experiments/v3_data/acquire.py`; auditing is in the adjacent `audit.py`. The shared interpreter is `/home/usatovpavel/edu/UtilsAI/.venv/bin/python`. No new Python environment is created. Network concurrency is at most four per command, and acquisition commands must run sequentially. Requests retry transient failures up to four times, with bounded connection/read timeouts; unresolved failures remain explicit. The scientific resource allocation is two CPU cores and four GiB RAM.

Each initial SIA request specifies only a small `POS=CIRCLE`, `COLLECTION=spherex_dr1`, `RESPONSEFORMAT=VOTABLE`, and bounded `MAXREC=512`. Every exact URL, raw XML and XML hash are retained under `metadata/<group>/`. Selection uses returned metadata rather than invented exposure identifiers. Each native cutout appends `center=RA,DEC&size=0.12` to its real IRSA parent FITS URL. These native 70-by-70-pixel MEFs are approximately four MB, including the mission ePSF table. Cutouts preserve detector orientation, WCS, physical exposure timing, IMAGE, FLAGS, VARIANCE, ZODI, EPSF and WCS-WAVE. No survey mosaic substitutes for an exposure.

Every successful file has exact URL, byte count, SHA-256, physical OBSID, detector and SIA start/end MJD in its group's `downloads.json`. Failed requests are kept separately in `download-failures.json`; successful-manifest rows contain only usable bytes. Development files are under `development/`; final bytes are under `quarantine_final/` and have a separate path boundary. Final FITS bytes can be hashed but are never opened by the audit's final branch. Before scientific work, the audit recomputes hashes and checks no exposure is shared across parents or splits.

The instrument ePSF is already pixel-convolved; it must be sampled at native pixel centers without another pixel convolution. Parent-image pixel positions follow the official cutout transform `parent_x = 1 + cutout_x - CRPIX1A` and the analogous y transform. This experiment is restricted to SWIR detectors 1–3 with `EPSF.DETCOORD=sky`; it does not claim correct MWIR detector-coordinate transformations. Native and registered coordinate frames must remain explicit. The existing `training/evaluate_background.py` provides the physical response projection and rejects unsupported detectors/frames.

## Required evaluation accounting

Use unmodified controls first and keep every real candidate's identity unknown. Inject sparse sources into the same native physical exposures using local ePSFs, exact WCS registration, masks and physical midpoint hours. No truth coordinates may enter detection or scoring. Source addition after registration does not constitute a raw-detector simulation, added photon noise, or variance update; report these limits explicitly.

Declare seed ranges, positions/directions, speed and brightness matrix, handling of missing/off-field support and fixed match tolerance before final execution. Do not move planned off-grid or masked points into coverage. For each parent field report all planned trials, finite-center-coverage-eligible subsets, detector completeness before ranking, and unique-object recovery at both one-review and three-review budgets for the identical detector plus heuristic and frozen model. State peak caps, candidate counts, actual temporal coverage and warnings. Exclude preexisting control matches from attributed discovery counts; show ambiguous/preexisting-match counts and raw spatial matches separately. Report brightness/speed subsets without treating injections as independent parent fields. Never call unmodified real candidates negatives, or infer precision, false-positive rate, calibrated probability, or survey-wide generalization from this experiment.
