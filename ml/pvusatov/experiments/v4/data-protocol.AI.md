# V4 prospective native-data cohort

The V4 data agent owns `data/` only. Frozen V3 scientific code, model weights, runtime and evidence are unchanged. New raw native observations live under `/tmp/spaceapps-v4-native-data/`; metadata, scripts, exact compressed query evidence and handoff manifests are published under this V4 directory. The coordinator owns model selection, final freeze, final authorization and release decisions.

`data/partition-plan.json` was written before any IRSA query or V4 pixel access: SHA-256 `55e0203db48bc294c6b1f4999d0582d1d9030d9e3e1b558d9f00364ac797e6cd`. It fixes eight new train, eight new development-validation and twelve quarantined-final sky parents. Half of each split has Galactic |b|≤10° and half is off-plane; detector preferences balance SWIR D1–D3. The deterministic Galactic 15° grid uses maximum minimum separation from all prior/existing centers, with declared tie-breaking. Minimum new-to-old sky separation is 16.278° and minimum V4 parent separation is 17.964°. All 200 V3 physical OBSIDs plus ten additional legacy fixture OBSIDs are excluded, across all crops, processing versions and detectors. Every derivative remains in its physical sky parent and split.

Cadence tiers were fixed prospectively: prefer eight epochs spanning at least two hours within 48 hours, then eight within 168 hours, then six–seven within those windows, and finally an explicitly constrained three-or-more epoch group. Within a tier prefer the declared detector and earliest physical date. No sky-parent or exposure replacement may follow model outcomes. All 28 live metadata queries supplied eight epochs spanning at least two hours in 48 hours with the preferred detector; no cadence/detector fallback was required. The exact prospective selection SHA-256 is `eacc056ab2506487ee57228e1cf8c634f80e728318ef51658f6b471b267d3ef1`.

Queries use the official IRSA SIA `spherex_dr1` collection, a 0.001° positional circle, and a predeclared 512-row limit with a 4,096-row overflow retry. At most four network workers run. Cutouts use actual official IRSA IBE parent URLs with `center=RA,DEC&size=0.12` degrees, retaining the complete native MEF and orientation. The analysis region is six by six arcminutes at 6.15 arcsec/pixel with the `motion` mask policy. Transfer errors and bounded retries remain recorded; retrying the same missing URL does not silently choose another field, exposure or processing version.

`data/query-evidence/` publishes exact compressed VOTABLE and discovery bytes for all 28 queries (2,496,883 compressed bytes). `query-provenance.json` records URLs and compressed/uncompressed digests; SHA-256 `446b8527f595ebb5e4fac2f1041e729bc7b0eb9a1b86c015e48c76f8b8dd3cca`. `audit_selection.py` replays the selection offline from those exact metadata rows. `selection-audit.json` confirms all 224 selected physical observations are unique across V4 parents and disjoint from the 210 excluded observations. These are metadata checks, not recovery outcomes.

`data/development-handoff.json` is incremental and includes only complete train/development-validation groups, with center, native physical times, detector, region and an exact eight-row downloads manifest. Completed per-parent files under `data/manifests/development/` are immutable; consumers should snapshot the handoff/hash they use. Per-source URLs, byte hashes, OBSIDs and all mission extension information remain available. The handoff does not label unknown real controls as negatives.

`data/final-quarantine-audit.json` and `data/manifests/quarantine_final/` contain **final metadata only**. Final raw files are opaque byte downloads until a coordinator-approved model/code freeze and explicit final authorization. The data agent may hash bytes and validate FITS headers, but does not load final pixel, variance, flag or ePSF arrays, register them, generate injections, extract features or score models. The header scanner reads header blocks and seeks over each HDU payload; a traced-stream regression fails if any image payload is read. It checks IMAGE, FLAGS, VARIANCE, ZODI, EPSF and WCS-WAVE preservation, dimensional consistency, celestial WCS, physical OBSID, detector and ePSF convention. Failed transfers are explicitly pending rather than supplied as fabricated observations.

New V4 TRAIN-only axis/coverage verification used 24 exposures across D1–D3. A positive native ePSF marker offset (+1,+2) was sampled on native axes and WCS-projected once; maximum registered centroid discrepancy was 0.1076 pixels, below the engineering check's fixed 0.3-pixel tolerance. IMAGE and EPSF `DETCOORD=sky` and oversampling five agree. This repeats the frozen V3 orientation evidence on new fields: SKY is the common SWIR detector view, not north-up. The official sources remain the [SPHEREx Explanatory Supplement](https://irsa.ipac.caltech.edu/data/SPHEREx/docs/SPHEREx_Expsupp.pdf), version 2.1 dated 2026-11-10, pages 52/59/60/74/81, PDF SHA-256 `9f3085cea74c6cdb647cc373bef27aaae50e394d348402e68ea2558ea06011cd`, and [IRSA's SPHEREx PSF tutorial](https://caltech-ipac.github.io/irsa-tutorials/spherex-psf/). Source, input and numerical evidence hashes are in `development-quality-orientation.json` (`e42921bdb87c14b40b57f57f3f38cfc0f783a4bee1fc14d6fd921637cab0c8b2`). No MWIR orientation, empirical shape fidelity, calibrated photometry or real-object precision is claimed.

Existing V3 train/validation data may be reused only as development. Published V3 FINAL results are neither fresh V4 holdout evidence nor a source for V4 model selection. All V4 unknown real controls stay UNKNOWN. Planned trials, finite-coverage eligibility, preexisting-control ambiguity and parent-level uncertainty must remain separate in later evaluation. This document is acquisition/provenance guidance, not an inference result or final-run authorization.
